# 多模态面试训练系统规格说明书（已交付基线与企业级演进目标，v1.1）

日期：2026-11-05　状态：已交付基线（P0 文字、P1 语音、P2 视频录答）＋演进规格（实时视频房间、企业增强）　适用项目：言阶／面试情景模拟训练与话术优化系统

## 1. 目标与定位

在已交付的文字、语音和视频录答能力上，继续建设可练习、可回放、可解释、可复测的面试训练产品。三种模式共用岗位、题目、追问策略和四维内容评分标准，但各自提供不同的交互与反馈：

| 模式 | 用户体验 | 独有训练价值 | 不成立的简化做法 |
|---|---|---|---|
| 文字面试 | 面试官逐轮提问，候选人打字回答；可计时、追问和修改 | 练答案结构、岗位针对性、事实证据与书面表达 | 固定问答模板＋一段笼统总评 |
| 语音面试 | 面试官出声提问，用户直接说话；系统自动判断说话结束并接续 | 练临场组织、语速、停顿、口头赘词和听后作答 | 录音→转文字→按文字模式打分 |
| 视频面试 | 摄像头自我预览、面试官语音/可视角色、限时作答；可按问题回看 | 练镜头前陈述、技术准备、作答节奏与自我复盘 | 保存一段视频文件却没有题目、时间线和反馈 |

产品用途是**训练与教练反馈**，不是自动招聘筛选或录用决策。报告要显示证据和不确定性；不能凭表情、面貌、口音、性别、年龄、背景环境推断人格、情绪或岗位能力。对候选人公开题目规则、评分维度、录制选择和数据去向。

## 2. 对标依据与设计取舍

- [HireVue 视频面试](https://www.hirevue.com/platform/online-video-interviewing-software?webvar1=homepage)强调结构化问题、实时/按需面试、评估指南与可分享记录；本项目借鉴“岗位能力→题目→证据→评语”的结构，不照搬招聘筛选业务。
- [HireVue AI 可解释性说明](https://www.hirevue.com/wp-content/uploads/2024/09/HV_2024_AI-Explainability-Statement.pdf)明确其评估链路为转写、理解回答、评分，且不分析面部、肢体或声调；本项目将内容评分与表达训练指标分开，并禁止伪科学式情绪/性格评分。
- [Yoodli 面试练习](https://support.yoodli.ai/en/articles/9550465-practice-with-yoodli)提供角色设定、动态追问、麦克风/摄像头练习及训练后分析；本项目借鉴即时追问和训练复盘，但指标只服务用户改善表达。
- [Talview 候选人支持说明](https://pages.talview.com/cognizant/faq/)体现设备预检、网络异常处理、断点恢复和问题级回看是完整视频体验的一部分；这些都进入本项目验收条件。
- 浏览器采集使用 [W3C Media Capture](https://www.w3.org/TR/mediacapture-streams/) 与 [MediaStream Recording](https://www.w3.org/TR/mediastream-recording/) 能力；录制编码须在运行时检测支持情况。字幕与同步回放参考 [W3C 媒体无障碍要求](https://www.w3.org/TR/media-accessibility-reqs/)。

以上是公开产品资料和标准形成的演进参考。本项目是单用户训练产品，不做招聘筛选；现有能力与演进目标以第 3 节和第 9 节为准。

## 3. 现状与差距

实际运行项目位于 `D:\graduation_design`。文字模式由 `TrainingView.vue`、`training/service.py`、`graph.py` 和 SSE 支撑；`evaluations/service.py` 采用四维评分。语音模式有 `voice/router.py`／`voice/session.py` 的豆包 Seeduplex WebSocket 通道，以及 `voice/pipeline.py` 的本地 Silero VAD → faster-whisper → DeepSeek → TTS 通道；`infrastructure/narration.py` 为语音合成提供豆包 seed-tts-2.0、edge-tts 与系统语音回退。

视频模式由 `VideoInterviewView.vue` 用 `getUserMedia`、`MediaRecorder` 录制**完整一段**并附题目时间轴上传；`video/router.py::_split_turns` 按词级时间戳切出各题转写，`video/metrics.py` 分析出镜率、看镜头、头稳、构图、光线等表现指标。`recordings/storage.py` 提供签名回放，`tasks/service.py` 异步执行转写、镜头分析、建会话和评分。**尚未实现**实时视频面试官、按题物理分段存储、正式设备预检和教练授权批注；这些是后文的演进要求。

## 4. 用户与业务流程

### 4.1 角色

- 学员：配置岗位与训练目标，完成练习、查看证据、管理媒体数据。
- 教师/教练：经学员明确授权，查看脱敏报告与指定片段并给人工批注；默认无权看原始音视频。
- 管理员：管理场景、题库、模型配置和运行质量；查看聚合指标，访问个人媒体须有单独审计授权。

### 4.2 统一流程

`选择岗位与面试类型 → 选择文字/语音/视频 → 阅读规则及媒体授权 → 设备预检 → 正式练习 → 每轮持久化 → 自动生成带证据报告 → 针对弱项复练 → 新题复测`。

开始前确定岗位、级别、面试类型（行为/情景/专业/压力）、目标时长、难度、语言、模式。系统先给面试提纲与评分 rubric；正式开始后问题按提纲抽取，追问围绕候选人上一答中的具体事实，不直接给答案。初测与复测使用不同题目，保留同一 rubric。每轮只提一个主问题；候选人可以请求重听、跳题或结束，行为记入事件日志。

### 4.3 文字模式（T）

| 编号 | 要求 | 验收 |
|---|---|---|
| T-01 | 显示题目、可选思考倒计时、答题计时和剩余轮次；计时可在无障碍设置中关闭 | 刷新后计时与轮次状态一致 |
| T-02 | 面试官依据岗位能力和上一答动态追问“做了什么、为什么、结果如何”等缺口 | 追问含可定位的前文事实，不能编造用户经历 |
| T-03 | 回答先保存草稿再提交；断网重连不重复提交；提交后才进入下一轮 | 同一请求 ID 最多产生一轮消息 |
| T-04 | 报告按问题显示 STAR 完整度、岗位匹配点、空泛表达和可执行改写 | 每条建议关联原回答片段和题目 ID |

### 4.4 语音模式（A）

| 编号 | 要求 | 验收 |
|---|---|---|
| A-01 | 面试官问题通过 TTS 播放，同时提供可开关字幕和重听；支持打断、暂停和耳机输出 | 播放中说话不会把 TTS 当作用户答复；字幕可读 |
| A-02 | 麦克风实时采集，VAD 判断起止；实时转写只作字幕和内容分析输入，保留词级/句级时间戳与置信度 | 用户可人工修正转写；低置信度片段标为待核对 |
| A-03 | AI 在用户说完后自然追问；允许用户点“我说完了”避免 VAD 误判 | 正常网络下从结束发言到面试官开始回应 p95 ≤ 3 秒（目标值，须实测） |
| A-04 | 单轮展示有效发言时长、语速区间、长停顿、口头赘词及打断次数；全部可点击定位音频 | 音频时间轴与字幕偏差 p95 ≤ 500 ms；人工抽检指标准确度 |
| A-05 | 语音质量差或 ASR 低置信时请求重述/文字修正，不直接给低分 | 噪声样本测试中出现“无法可靠评估”而非臆断分数 |

语音内容四维评分基于识别出的回答文字；语速、停顿等作为**表达训练指标**单独展示，不按口音或音色扣分。人工修正转写和赘词误报标注属于演进要求。

### 4.5 视频模式（V）

**已实现的是按需视频录答**：用户按题目顺序录制一段视频，上传后异步转写、按题目时间窗切分回答、生成四维评分和镜头表现指标，并在报告中回放。实时视频训练房间（面试官语音、虚拟角色与实时追问）属于演进目标。真人面试官多人实时通话需另行设计 WebRTC 房间、身份与权限。

| 编号 | 要求 | 验收 |
|---|---|---|
| V-01 | 入场检测摄像头、麦克风、扬声器、权限、网络和预览；可选择背景模糊或关闭镜头并降为语音模式 | 拒绝权限、设备中途拔出、弱网均有明确恢复路径 |
| V-02 | 展示当前问题、计时、面试官状态、实时字幕与自我预览；录制状态始终可见 | 开始/暂停/停止录制有可见反馈，结束后摄像头轨道释放 |
| V-03 | 音视频按问题分段保存，建立 `questionId + startMs/endMs + transcriptSpan` 对齐关系 | 点击报告证据能跳到对应片段，时间偏差 p95 ≤ 500 ms |
| V-04 | 报告提供“题目→回答→关键片段→建议→再练一次”；可并排比较两次回答的内容结构与时长 | 教练建议能打开原片段；新练习保留独立题目和版本 |
| V-05 | 展示出镜率、看镜头、头稳、构图和光线等镜头表现与技术质量指标；不据此推断人格、诚信或录用能力 | 指标可复现，报告不含“性格/诚信”算法结论 |
| V-06 | 提供逐题视频自评清单：镜头位置、信息组织、开场与收尾；用户可给片段加标记，并选择授权教练做人工批注 | 自评和批注均链接具体时间段；批注者、时间与撤销授权可追溯 |

当前视频流程需上传录像才能分析和回放；“不保存媒体仍可完成视频训练”的选项尚未实现。现有整段录像＋题目时间窗解决了逐题转写与回放的一部分需求，但不等于按题物理分段或实时视频房间。

## 5. 评分、反馈与质量门槛

1. **内容评分：四维**。对应关系为：内容与逻辑 `logic`、贴合问题 `relevance`、信息完整 `correctness`、表达干净 `concision`，每维 1–5 分并有行为锚点。得体性不再单独评分；命令式、推卸责任、绝对化表达只列为风险提示。历史字段 `appropriateness` 仅为兼容旧数据保留。
2. **评分稳定性**。默认调用模型 3 次，逐维取中位数并记录波动；最大波动 ≥ 2 档时标记为不稳定，建议人工复核。客观锚点按连接词/结构、重复与填充、问题相关性、四要素等规则计算，最终每维按模型分 70%＋客观分 30% 混合，极低客观分会压制虚高模型分。
3. **证据验证**。`evidence.quote` 须能在对应用户回答中定位；当前实现比较前会去除空白与标点，因此允许标点规范化，不能宣称严格逐字连续匹配。无效证据丢弃。`resumeQuote` 只有同时出现在简历原文和该轮提问中才保留，否则置空；建议包含轮次、原话、原因与下一步动作。
4. **过程反馈**。文字统计口头语等文本指标；语音提供词级时间戳、语速、停顿和填充词；视频追加镜头表现、技术质量和问题级回放。过程指标与四维内容分分别展示。
5. **模型失效与重算**。模型调用全部失败时报告标记 `degraded=true`，且不生成新计划；模型恢复后可对降级报告调用 `POST /evaluations/{session_id}?force=true` 重算。ASR、TTS 或媒体任务失败应另行显示，不能伪装成正常评分。
6. **人工评测**。`backend/scripts/export_annotation_batch.py` 与 `score_agreement.py` 已提供标注导出和一致性统计工具，人工样本及真实模型评测结果仍待补。建议准备至少 50 份去标识化样本，覆盖岗位、模式、设备与口音；四维平均绝对误差 ≤ 0.75 分、证据定位率 ≥ 95% 为待校准目标，不能当作现有成绩。

## 5A. 训练计划体系（已实现）

每次**非降级且符合条件的新评分**生成带序号的计划（#1、#2…）；未完成计划累积保留，最多 3 份为 `ACTIVE`，更早的转 `ARCHIVED`。由计划任务发起的训练不再重复生成新计划。计划任务按顺序完成，`SCENE`／`VIDEO` 要提交属于本人、同场景、已完成且未重复使用的新会话；文字练习至少 6 轮，视频至少 2 段作答。计划任务中的训练完成后可自动回填任务进度。当前代码实际使用 `ACTIVE`、`COMPLETED`、`ARCHIVED` 状态。

## 6. 技术结构与接口约定

```text
Vue 训练页面
  ├─ 文字：REST 创建会话 + SSE 流式追问
  ├─ 语音：WebSocket → 豆包实时双工，或本地 VAD/Whisper/DeepSeek/TTS 管线
  └─ 视频：getUserMedia + MediaRecorder 整段录制 → 上传并排队分析
                                     ↓
FastAPI → MySQL 会话/评分/任务 → 本地私有录制目录 + HMAC 签名回放
                         ├─ Redis：会话状态与限流
                         └─ 异步任务：转写 → 镜头分析 → 建会话 → 四维评分
```

现有语音使用 WebSocket 双向通信：输入 16 kHz，输出 24 kHz，同时最多 2 路，超限关闭码 `4029`；`4001` 表示未配置，`4003` 上游断开，`4004` 上游不可用，`4005` 本地管线启动失败。本地管线的模型体积与依赖须按部署包实测，不能用“约 250 MB、无 torch”作为固定承诺。当前视频存单个文件与题目时间窗，不把视频送给大模型；未来按题物理分段、对象存储直传、真人 WebRTC 房间属于演进设计。浏览器录制格式须通过 `MediaRecorder.isTypeSupported()` 选择并做手机实机测试。

统一媒体直传和完整状态机仍需新增对象：`InterviewConfig`（岗位/模式/rubric 版本）、`QuestionTurn`（题目/追问来源/轮次）、`TranscriptSegment`（说话人/起止/置信度/修订）、`MediaAsset`（类型/对象键/校验和/保留期）、`SessionEvent`（权限变化/重连/降级）。当前已有 `TrainingSession`、`Message`、`Evaluation`、`EvaluationEvidence`、`AnalysisTask` 等实体，迁移头为 `20261104_0031`；演进时应复用或迁移现有实体，避免平行建立两套报告。

当前 `/api/v1` 已有 `/auth`、`/scenes`、`/training-sessions`、`/evaluations`、`/training-plans`、`/courses`、`/scripts`、`/stories`、`/dashboard`、`/ability`、`/video-interviews`、`/voice`、`/tasks`、`/admin` 等功能域。以下 `/api/v2` **仅为统一状态机与媒体直传的演进草案**；落地时保持 `/training-sessions` 兼容：

- `POST /api/v2/interviews`：创建模式化会话，返回配置快照及幂等 ID。
- `POST /api/v2/interviews/{id}/start|pause|resume|finish`：状态变更，服务端校验合法转移。
- `WS /api/v2/interviews/{id}/realtime`：音频片段、字幕、VAD、追问、TTS 和心跳事件；每帧含序号与时间戳。
- `POST /api/v2/interviews/{id}/media/uploads`：申请分段直传；完成后校验大小、类型、校验和并生成私有对象。
- `PATCH /api/v2/interviews/{id}/transcript/{segmentId}`：用户修正转写，触发相应内容评分重算。
- `GET /api/v2/interviews/{id}/report`：返回评分、模型/算法版本、证据与降级状态。
- `GET /api/v2/interviews/{id}/media/{assetId}/playback`：短期授权播放地址；禁止跨用户访问。

上述 v2 会话状态机规划为 `CREATED → DEVICE_CHECK → READY → IN_PROGRESS ↔ PAUSED → PROCESSING → COMPLETED`，另有 `INTERRUPTED`、`FAILED`、`DELETED`。当前训练会话主要使用 `ACTIVE`／`FINISHED`；视频分析任务另有 `PENDING`／`RUNNING`／`DONE`／`FAILED`，在转写、镜头分析、建会话、评分、完成等阶段更新进度，失败可重试。不能把规划状态写成已上线状态。

## 7. 安全、隐私、可用性

- 当前录制文件默认保留 30 天，回放使用 30 分钟有效的 HMAC 签名地址；生产环境可启用每 6 小时一次的自动清理，开发环境可手动触发。数据库没有训练会话时跳过孤儿文件回收，避免误删。
- 删除训练记录会级联清理其消息、评分、证据和录像，并回退其他计划中引用该训练的任务进度；跨用户读取按 404 返回，避免暴露资源存在性。删除与恢复演练仍应覆盖实际部署存储。
- 麦克风、摄像头需浏览器授权。媒体保存、教练访问的细粒度同意与撤销属于演进要求；当前录像放在私有本地目录，不能把未来的 MinIO/S3 私有桶、直传、病毒扫描或静态加密写为已实现。
- 提供实时字幕、键盘操作、音量控制、重听、暂停、文字替代路径；视频评价不得因用户关闭摄像头而降低内容分。
- 成本限制：单用户每日训练时长、并发会话数、音视频大小、ASR/TTS/LLM 用量上限可配置；界面在限额前提醒并允许保存进度。
- 管理端已展示评分总数、降级率、平均评分耗时、任务失败率和录制占用；实时延迟、转写低置信占比、媒体上传失败率、单位训练成本属于后续监控指标。CSV 导出列名应与四维名称保持一致。

## 8. 验收与交付顺序

| 阶段 | 交付内容 | 完成定义 |
|---|---|---|
