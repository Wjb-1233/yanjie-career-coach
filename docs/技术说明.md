## 2. 模型

### 2.1 文本模型（面试官 / 评分 / 微课 / 话术）

```
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

统一走 `app/infrastructure/llm.py` 的 `LlmGateway.complete_json()`，OpenAI 兼容协议，要求模型返回 JSON。

四处调用：

| 用途 | 入口 | 提示词位置 |
|---|---|---|

| 四维评分 | `app/features/evaluations/service.py` | `SYSTEM_PROMPT` |
| 微课生成 | `app/features/plans/generation.py` | `LESSON_SYSTEM_PROMPT` |
| 话术三风格 | `app/features/scripts/service.py` | `SYSTEM_PROMPT` |

### 2.2 语音模型（端到端实时对话）

```
供应商：火山引擎 · 豆包端到端实时语音大模型（Seeduplex）
地址：wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue
模型：1.2.6.1
音色：zh_female_xiaohe_jupiter_bigtts（小何）
```

鉴权走旧版控制台方式（服务端加头，前端拿不到密钥）：

```
X-Api-App-Key:    PlgvMymc7f3tQnJ6
X-Api-App-ID:     9034864224
X-Api-Access-Key: <DOUBAO_REALTIME_ACCESS_TOKEN>
X-Api-Resource-Id: volc.speech.dialog
X-Api-Connect-Id:  <uuid>
```

**全部为 JSON 文本帧**，关键事件：

| 方向 | 事件 | 作用 |
|---|---|---|
| 上行 | `session.create` | 建会话，带 instructions 与音色 |
| 上行 | `input_audio_buffer.append` | base64(PCM 16k int16)，每包 640 字节 = 20ms |
| 上行 | `input_audio_buffer.commit` | 强制判停 |
| 上行 | `speech_text_buffer.commit` | 让面试官先说一句（打招呼） |
| 上行 | `response.cancel` | 打断播报 |
| 下行 | `conversation.item.input_audio_transcription.*` | 用户语音转写 |
| 下行 | `response.output_text.done` | 面试官这句话的文本 |
| 下行 | `response.output_audio.delta` | base64(PCM 24k int16) 音频块 |

> 注意：音频输入采样率**只支持 16000**，输出**只支持 24000**；发包节奏需贴近真实时间，过快或过慢都会被服务端拒绝。

### 2.3 两套语音引擎

语音对练页右上角可切换引擎：

| 引擎 | 链路 | 特点 |
|---|---|---|
| **标准引擎**（默认） | 浏览器 ⇄ 后端代理 ⇄ 豆包 Seeduplex | 端到端语音，音色自然、延迟低；依赖火山服务 |
| **本地管线** | 浏览器 ⇄ pipecat（Silero VAD → faster-whisper → DeepSeek → 系统语音） | 完全本地可控，火山不可用时兜底；语音识别与合成质量略低 |

本地管线用 `pipecat` 编排（`app/features/voice/pipeline.py`）：

```
transport.input() → stt(whisper) → 字幕 tap → 上下文聚合 → llm(deepseek)
                  → 字幕 tap → tts(系统语音) → transport.output()
```

- 传输层：`FastAPIWebsocketTransport`，自定义序列化器：二进制帧=裸 PCM，文本帧=JSON 字幕
- VAD：`SileroVADAnalyzer`（ONNX 推理，无需 PyTorch）
- 依赖：`pipecat-ai 1.15`，约 250 MB（含 onnxruntime、numba），不引入 torch

### 2.4 语音合成（微课旁白 / 话术试听）

旁白走豆包大模型语音合成 `seed-tts-2.0`：

```
接口  POST https://openspeech.bytedance.com/api/v3/tts/unidirectional
鉴权  X-Api-App-Id / X-Api-Access-Key / X-Api-Resource-Id: seed-tts-2.0
音色  saturn_zh_female_keainvsheng_tob（可爱女生）
情绪  按幕传入：封面 happy，正文 serious
```

- 音色是 2.0 的**角色音色**，与 `zh_female_xiaohe_jupiter_bigtts` 那类 1.0 音色不通用（会报 `resource ID is mismatched with speaker`）
- 情绪参数支持 `neutral / happy / sad / angry / surprise / gentle / serious`
- 文本按标点切句后逐句合成，句间留 0.45 秒停顿
- 降级链：豆包 → edge-tts（`zh-CN-XiaoxiaoNeural`）→ Windows 系统语音（SSML 调语速、停顿、重音）
- 输出直接是 mp3，不依赖 ffmpeg；时长用 `mutagen` 读取

### 2.5 并发与降级

- 同一时刻最多 **2 路语音会话**（`VOICE_SLOTS` 信号量）。超出时后端以 `4029` 关闭并返回「语音服务繁忙」，前端显示为可读提示
- 关闭码约定：`4001` 未配置、`4003` 上游断开、`4004` 上游不可用、`4005` 管线启动失败、`4029` 并发已满
- 豆包侧有会话数限制，短时间反复开关会触发 `ConnectionResetError`，冷却约 1 分钟

### 2.6 语音训练如何进入评分

```
结束通话 → 上传转写(可选录音) → 创建 VOICE 会话（channel=VOICE, engine=doubao|pipeline）
        → 自动 finish → 四维评分 → 报告页（含「表达节奏」与节奏建议）
```

若有 `planId`/`taskKey` 上下文，结束后会同时标记该计划任务完成。

### 2.7 视频面试

浏览器录一段摄像头录像，后端拆成逐题作答并分析镜头表现。

```
浏览器（MediaRecorder，webm/VP8+Opus）
  → POST /video-interviews（sceneId + 题目时间轴 + 录像）
  → 音频：faster-whisper 词级时间戳 → 按题目时间窗切出每轮回答
  → 画面：MediaPipe FaceLandmarker（478 点，含虹膜）逐帧采样
  → 生成 VIDEO 会话 → 复用四维评分链路
```

镜头指标（全部客观可复现，不评价长相）：

| 指标 | 算法 |
|---|---|
| 出镜率 | 有脸帧 / 采样帧 |
| 看镜头 | 虹膜位于眼眶中部 + 头部偏转小于阈值 |
| 头部稳定 | 偏航/俯仰角标准差的倒数 |
| 构图 | 人脸中心与画面中心的距离 |
| 光线 | 采样帧平均亮度 |

依赖：`mediapipe 1.2` + 模型 `.models/face_landmarker.task`（3.7MB）。首次运行前下载一次：

```bash
curl -L -o backend/.models/face_landmarker.task \
  https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
```

## 3. 分数怎么来的

### 3.1 四维分档评分

评分维度（各 1—5 分，每档有行为锚点）：

| 维度 | 键 | 看什么 |
|---|---|---|
| 内容与逻辑 | logic | 结论、因果、取舍、可核查依据 |
| 贴合问题 | relevance | 是否正面回应问题核心与隐含关切 |
| 信息完整 | correctness | 背景 / 做法 / 结果 / 数据四要素 |
| 表达干净 | concision | 冗余、填充词、重点可辨性 |

得体性不再参与打分，只在命中「命令式 / 推卸 / 绝对化」时作为风险提示。

**评分流程**

```
① 规则算客观分（objectives.py）
   结构连接词密度、重复率、填充词密度、关键词覆盖、四要素命中
② 模型先写「满分回答」，再按分档细则定档，逐维给证据
③ 3 次采样取中位数，记录每维波动；波动 ≥2 档标记「建议人工复核」
④ 最终分 = 0.7 × 模型分 + 0.3 × 客观分（客观分 <0.25 时压制到 3 分以内）
```

命中缓存前，`stability` 会记录采样数与最大波动，报告页直接展示「3 次采样评分一致」。

### 3.2 场景维度匹配

场景没有人工标注「练哪个维度」，用两条证据估计 `scene_fit`：

```
① 关键词：标题 / 目标 / 背景命中逻辑、追问、数据、简洁等词
② 行为证据：该场景历史评分里哪个维度平均分最低
最终 fit = 0.55 × 关键词 + 0.45 × 历史
```

推荐时按 `0.55 × 维度匹配度 + 0.45 × 难度接近度` 排序，两场尽量覆盖两个最弱维度，
并保证最弱的那一场排在前面。

### 3.3 能力建模与排程

```
skill_states（user × dimension → Elo 分）
  每次评分：expected = 1/(1+10^((场景难度-能力值)/400))
            rating += 24 × (实际表现 - expected)
场景难度：入门 920 / 中级 1000 / 进阶 1080，按历史均分 ±40 修正
错题复习：due_at 按 1 → 3 → 7 → 15 天递增
计划生成：能力最接近且维度匹配的 2 个场景（第二场为视频面试）+ 复盘批注 + 最弱维度微课，共 3 个任务卡（历史计划可能只有 1–2 个任务）
计划编号：每位学员的计划带自增序号（#1、#2…）；每次新评分都会生成一份新计划，未完成的旧计划保留，最多同时进行 3 份，更早的转为 `ARCHIVED`
计划任务训练：会话记录 `plan_id`/`task_key`，结束时自动勾掉对应任务；这类会话至少 6 轮才能结束
降级评分（`degraded=true`）不生成计划，也不更新计划进度
```



### 3.4 综合分

```python
overall = round(mean(四维) * 20, 1)   # 百分制
```

例：`2,3,3,3` → `2.75 * 20 = 55.0`。

### 3.5 评分的可信性约束

1. **逐字证据**：每个维度给出 `evidence`，`quote` 必须是用户原话的连续片段，不许改写拼接
2. **满分参考**：每条建议附 `reference`（面试官期望的完整回答），要求保留用户真实事实、不编造经历
3. **简历引用校验**：若 `resumeQuote` 不为空，必须同时出现在简历原文与该轮提问中，否则代码直接置 `null`
4. **可对比**：报告展示与上一次的维度差值（↑2 / ↓1）

### 3.6 降级路径

模型不可用时走 `fallback_evaluation()`：按关键词与长度给中性分（内容与逻辑 / 贴合问题 / 信息完整 / 表达干净），字段标注 `degraded`，报告页提示「本报告由本地评分规则生成」。

## 4. 面试官怎么说话（状态机）

`app/features/training/graph.py` 使用 LangGraph `StateGraph`，确定性编排：

```
safety（风控） → advance（推进阶段） → prompt（拼提示词）
```

> 为什么用 LangGraph：当前是线性三节点，但编排层已经把「阶段推进、风控标记、提示词拼装」拆成独立节点，后续要加条件路由（例如风控命中时跳过追问、提前收尾）只需要加边，不需要改调用方；这也是把它和业务逻辑分开的原因。

阶段推进（12 轮封顶）：

```
< 3 轮   OPENING
3–7 轮   DISCOVERY
≥ 8 轮   CHALLENGE
最后一轮  CLOSING（只收尾，不再提问）
```

每轮提示词注入：场景背景与目标、场景核心思想、面试阶段边界、难度、必问题/JD 考察点、简历原文、上一轮回答、风控标记（命令式/推卸/绝对化）。

## 5. 微课与视频

### 5.1 微课生成

`app/features/plans/generation.py::generate_lesson_only()`，输入：维度分数、建议、用户原话、场景、候选课件。输出固定 3 步 + 1 道练习。同维度有多门课时由模型挑选，结果缓存，点「换一门」强制重生成。

### 5.2 视频渲染（两套引擎）

| 引擎 | 实现 | 特点 |
|---|---|---|
| `python` | `app/features/lessons/video.py` | Pillow 静态分镜 + ffmpeg 合成，快（约 10 秒） |
| `remotion`（默认） | `app/features/lessons/remotion_render.py` + `video/` | React 组件动画，开场/步骤切换/进度条，画面更精致（约 40–60 秒） |

**Remotion 流程**：

```
微课 JSON
  → 每个分镜单独合成旁白（豆包 TTS，逐幕情绪不同）
  → 用 mutagen 读时长，slideDurations 驱动 React 时间轴
  → 每幕一个 Sequence + Audio，音频即分镜音轨
  → remotion CLI 渲染 1920×1080 mp4（含音轨）
  → 按「内容哈希 + 引擎」缓存到 backend/static/lessons/
```

接口：`POST /api/v1/training-plans/{id}/lesson/video`
请求体 `{task_key, force, engine}`，`engine` 取 `auto|python|remotion`，默认读 `LESSON_VIDEO_ENGINE`。

前端进入微课页会先调 `GET /api/v1/training-plans/{id}/lesson/video` 查缓存：命中就直接内联播放并列出章节，未命中才需要点「看视频版」等待渲染。章节时间点在渲染时写入同名 `.json`。

## 9. 音频 / 视频回放

语音与视频对练的原始录音都会留存，训练记录和报告页都能回放。

```
浏览器上传 → 保存到 backend/static/recordings/<uuid>.<ext>
          → training_sessions.recording_path 记录文件名
          → GET /media/recordings/<file> 提供播放（StaticFiles）
```

- 语音：`POST /voice/sessions` 的 `audio` 字段
- 视频：`POST /video-interviews` 的 `video` 字段
- 限制：单个文件 200MB，支持 webm / mp4 / wav / m4a / ogg / opus / mp3
- 回放入口：训练记录列表的「回放」按钮（弹窗），以及报告页「现场回放」面板
- 回放地址带**短期签名**：`/media/recordings/<file>?token=<hmac>&expires=<ts>`，默认 30 分钟有效
- 签名用 HMAC-SHA256（密钥取 `RECORDING_SIGNING_SECRET`，缺省用 JWT 密钥），文件名校验防止路径穿越
- 链接过期后播放器会收到 403，前端提示「回放链接已失效，请刷新页面」
- 注意：这把「谁登录谁能看」变成了「拿到链接 30 分钟内能看」，链接本身不要外传

**保留与清理**

| 项 | 说明 |
|---|---|
| 保留期 | `RECORDING_RETENTION_DAYS`，默认 30 天 |
| 自动清理 | 仅生产环境每 6 小时清一次（`RECORDING_JANITOR_ENABLED`，其他环境用后台按钮手动触发） |
| 孤儿回收 | 目录里没有会话引用的文件一并删除；数据库一条会话都没有时跳过，避免误删 |
| 手动管理 | `GET /admin/recordings` 看占用，`POST /admin/recordings/purge?days=N` 立即清理 |

## 10. 内容生产：批量生成场景

```bash
# 预览（不写库）
python scripts/generate_scenes.py --category "技术一面" --industry 互联网 --count 3 --dry-run

# 生成草稿（默认不开放，需后台审核）
python scripts/generate_scenes.py --category "交叉面 / 总监面" --count 5

# 查看待审核草稿
python scripts/generate_scenes.py --review
```

校验规则：标题必填且查重、背景与目标必填、必问题 ≥2 条、维度限定为四维之一、
难度限定为入门/中级/进阶，不合格的场景会被跳过并打印原因。

加 `--verify` 会再做一次质量自检：让模型按真实度、区分度、可答性打分（0-10），
任一项低于 7 分的场景被淘汰，避免「格式合法但内容空洞」的场景进入草稿。

## 11. 评分一致性实验（人工标注）

用来回答「模型打分准不准」。分两步：

```bash
# 1) 导出样本（每行是一条证据，按四维轮流抽样）
python scripts/export_annotation_batch.py --size 40 --out annotation.csv

# 2) Excel 填 human_score（1-5 整数）后统计
python scripts/score_agreement.py --input annotation.csv --report docs/评分一致性.md
```

输出指标：

| 指标 | 含义 |
|---|---|
| Spearman | 排序一致性，对绝对分差不敏感 |
| MAE | 平均绝对误差（分） |
| 完全一致率 | 模型分与人工分完全相同的比例 |
| 一档内一致率 | 相差 ≤1 分的比例 |
| 偏差 | 模型均值 − 人工均值，正数代表模型偏高 |

实现只依赖标准库（手写秩相关），不引入 scipy。

## 12. 后台任务

视频分析走任务队列，状态落库、可恢复、可观测：

| 接口 | 用途 |
|---|---|

## 13. 题库版本化

题库可以导出成 YAML 放进仓库，改动走 diff 评审：

```bash
# 导出（默认只导出结构，不含运行数据）
```

导入时校验分类必填、问题至少一条、维度与难度限定在合法值内。

## 14. 已知限制

1. 四维 rubric 为自定义体系，非国家或行业标准，未做真人评分对照实验
2. 评分为模型主观判断，靠证据与引用校验约束，不能替代真人教练
3. 语音对话依赖火山引擎服务，短时间反复开关会话会触发服务端连接限制
4. 豆包语音合成按角色音色授权，换成未开通的音色会返回 `resource ID is mismatched`；网络异常时降级到 edge-tts 或系统语音，音色会有差异
5. 简历只支持 `.docx`，不解析 PDF 与扫描件
6. Remotion 首次渲染约 40–90 秒，依赖 Node 环境；未安装时自动回退 python 引擎
7. 表达节奏分析使用 faster-whisper 的 CPU int8，约 0.6–1 倍实时（GPU 需额外 CUDA 运行库）
8. 本地语音管线首次加载 Whisper 模型约 10 秒，之后常驻内存
9. 部分 Windows 环境里 httpx 默认 `trust_env=True` 会连不上模型服务，网关已固定 `trust_env=False`
10. 面试官编排目前是**线性三节点**（safety → advance → prompt），选用 LangGraph 是为了后续加条件路由与阶段状态机，不是当前必需

## 15. 市面产品对照与产品层增强

参考公开资料（HireVue、Interviewer.AI、Big Interview VideoAI、北森 AI 面试官、Yoodli），主流做法收敛为三条：

1. **评分必须可拆解**：北森用「知识点 → 技能 → 岗位」三层聚合，任何分数能追到题目与标准；
2. **内容分与表达分分开**：Big Interview 把「说了什么 / 怎么说的 / 技术质量」分三块；HireVue 明确不分析面部与声调；
3. **报告必须落到下一步**：Big Interview 的 Action Plan、Yoodli 的 drills、Google Interview Warmup 的 insight 都是练习入口。

据此补了四项产品层能力（不改架构）：

| 能力 | 实现 |
|---|---|
| 行动计划 | 报告顶部「接下来只做三件事」：最弱维度改写、砍一个口头禅、把一句空话换成具体结果，各带跳转 |
| 逐题考察点 | 每轮回放显示考察维度、该维得分与证据里缺什么（数据来自 `questionPlan` 与 `evaluation_evidence`） |
| 表达时间轴 | 停顿分布条，点标记跳到录音对应秒数（`delivery.pauses` + 签名回放） |
| 岗位能力映射 | `scenes.competency`（迁移 `20261105_0032`），分类映射到能力标签，场景卡与筛选可见 |
| 今日一练 | 看板「今天练什么」：优先计划下一步任务，其次到期错题，最后新训练 |

不做的事：外貌/穿着/表情/情绪打分、录用预测、单一总分排名。这些在招聘产品里存在，但不可验证且有合规风险。
