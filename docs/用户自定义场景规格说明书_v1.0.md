# 用户自定义场景 规格说明书（v1.0 草案）

> 状态：待评审　适用项目：言阶／面试情景模拟训练与话术优化系统
> 目标读者：开发、答辩评审、后续维护者

---

## 1. 背景与目标

现有 33 个内置场景覆盖校招常见阶段，但真实求职里用户面对的是**具体岗位、具体公司、具体 JD**。内置场景回答不了「我下周要面这家公司的这个岗，能不能先按他们的要求练一遍」。

本功能让学员**自己定义一场面试场景**：填岗位、背景、面试官角色、考察问题，然后像内置场景一样对练、评分、复盘。

成功标准（可验收）：

1. 用户 3 分钟内能创建一场可用的自定义场景；
2. 自建场景能完整走通「创建 → 对练 → 四维评分 → 报告 → 再练」；
3. 自建场景**不污染**公共题库，也不默认进入个性化计划；
4. 从 JD 起草的场景，其问题必须与 JD 里的要求对得上，且不编造公司事实。

## 2. 范围

**做**：创建、编辑、删除、预览、试练、评分、分享链接、提交管理员审核。
**不做**：多人协作编辑、企业级租户隔离、自定义评分维度（评分仍用四维 rubric）、自定义 AI 面试官声音。

## 3. 角色与权限

| 角色 | 权限 |
|---|---|
| 学员（创建者） | 增删改查自己的场景；试练；生成分享链接；提交审核 |
| 其他学员 | 只能通过分享链接**试练**，看不到编辑入口，不能改 |
| 管理员 | 查看待审核列表；通过后进入公共题库（标记来源）；驳回并填理由 |
| 教师/教练 | 只读查看被分享场景的报告（沿用现有教练链接） |

## 4. 用户流程

```
进入「场景训练」→ 点「创建我的场景」
   ├─ 方式 A：手动填写（表单）
   ├─ 方式 B：粘贴 JD → AI 起草 → 用户修改确认
   └─ 方式 C：从内置场景复制一份再改
→ 预览（看到面试官开场白与问题清单）
→ 「试练一场」（与内置场景完全相同的对练/语音/视频能力）
→ 结束后正常出四维报告
→ 场景详情页可：再练、编辑、分享、提交审核、删除
```

## 5. 字段设计

### 5.1 基本信息（必填）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 标题 | string | 4–60 字，去重（同用户） | 例：字节跳动-后端开发-二面 |
| 行业 | string | 2–30 字 | 默认「互联网」 |
| 岗位 | string | 2–40 字 | 例：后端开发工程师（校招） |
| 面试阶段 | enum | 内置 7 类 | HR 初面 / 技术一面 / 技术二面 / 交叉面 / HRBP 终面 / 高管终面 / 其他 |
| 难度 | enum | 入门 / 中级 / 进阶 | 影响追问深度与计划门槛 |
| 面试官角色名 | string | 2–30 字 | 例：技术负责人 |
| 背景 | text | 20–500 字 | 公司/团队/业务背景 |
| 考察目标 | text | 10–300 字 | 这场想练什么 |

### 5.2 对话素材

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 开场白 | text | 5–200 字 | 面试官第一句话；留空则由模型生成 |
| 必问题 | list | 2–8 条，每条 2–120 字 | 每题可选「考察维度」与「难度」 |
| 核心思想 | text | ≤200 字，选填 | 这场面试的评价基调 |
| 能力标签 | string | 选填 | 技术深度 / 沟通表达 / 协作与影响力 / 求职动机与稳定性 / 自定义 |

### 5.3 可选素材

| 字段 | 类型 | 说明 |
|---|---|---|
| JD 原文 | text | ≤4000 字；用于 AI 起草与岗位匹配评分 |
| 简历 | 复用现有 | 训练时仍可上传 .docx |

### 5.4 校验规则

- 必问题少于 2 条 → 拒绝保存（「一场面试至少要问两个问题」）
- 问题重复（相似度 >0.85）→ 去重并提示
- 标题与已有自建场景重复 → 提示改名
- 背景/目标为空 → 用岗位与阶段拼默认值，并标注「自动补全」
- 敏感内容（手机号、身份证、真实公司内部数据）→ 提示删除

## 6. 创建方式

### 6.1 手动填写

表单分三组：基本信息 / 对话素材 / 可选。支持随时保存草稿。

### 6.2 从 JD 起草（AI 辅助）

输入：JD 文本（必填）、岗位名、阶段、难度。
输出：标题、背景、目标、开场白、4–8 条必问题（带考察维度）。

提示词约束（写进系统提示）：

- 只能从 JD 里出现的要求生成问题，不得编造公司业务事实；
- 不生成「公司文化」「团队氛围」这类无法核实的断言；
- 问题以「考察点」形式给出，避免直接给答案；
- 输出 JSON，字段与表单一一对应。

用户必须在预览页逐条确认后才能保存，AI 起草的内容标「AI 起草，待确认」。

### 6.3 从内置场景复制

复制一份内置场景到「我的场景」，标题加「（我的版本）」，用户可改问题与背景。适合「内置场景不错，但我这个岗位有点不一样」。

## 7. 数据模型

优先复用现有 `scenes` 表，避免双表：

```sql
ALTER TABLE scenes ADD COLUMN owner_id VARCHAR(36) NULL;      -- NULL = 内置/公共
ALTER TABLE scenes ADD COLUMN visibility VARCHAR(16) NOT NULL DEFAULT 'public';  -- public | private | shared
ALTER TABLE scenes ADD COLUMN review_status VARCHAR(16) NOT NULL DEFAULT 'none'; -- none | pending | approved | rejected
ALTER TABLE scenes ADD COLUMN source VARCHAR(16) NOT NULL DEFAULT 'builtin';     -- builtin | user | ai_draft | copy
ALTER TABLE scenes ADD COLUMN reviewed_by VARCHAR(36) NULL;
ALTER TABLE scenes ADD COLUMN review_note VARCHAR(300) NULL;
ALTER TABLE scenes ADD COLUMN usage_count INT NOT NULL DEFAULT 0;
```

查询约定：

- 学员可练：`visibility='public' AND active=1`（内置 + 审核通过）**或** `owner_id = 当前用户`
- 分享试练：通过 share token 允许 `owner_id != 当前用户` 的只读试练
- 个性化计划推荐：只从 `source='builtin'` 或 `review_status='approved'` 里挑
- 题库导出：默认只导出 `builtin`

## 8. API 草案（`/api/v1/my-scenes`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/my-scenes` | 创建（支持 `draft=true`） |
| GET | `/my-scenes` | 我的场景列表（含草稿、审核状态） |
| GET | `/my-scenes/{id}` | 详情（仅 owner 或管理员） |
| PATCH | `/my-scenes/{id}` | 编辑（部分字段） |
| DELETE | `/my-scenes/{id}` | 软删除（有训练记录时提示） |
| POST | `/my-scenes/draft-from-jd` | AI 起草，返回表单结构，不落库 |
| POST | `/my-scenes/{id}/share` | 生成试练链接（复用 share 机制，7 天） |
| POST | `/my-scenes/{id}/submit-review` | 提交审核 |
| POST | `/admin/my-scenes/{id}/review` | 管理员通过/驳回 |

训练入口复用现有 `POST /training-sessions`，只需允许 `sceneId` 指向自己的私有场景。

## 9. 与现有能力的关系

| 能力 | 处理 |
|---|---|
| 四维评分 | 完全复用，不因自建场景改变 rubric |
| 追问编排 | 复用 `graph.py`，场景背景与目标注入同一位置 |
| 计划生成 | 自建场景**默认不参与**推荐；用户可在计划页手动「加入训练计划」 |
| 话术 / 故事 / 错题 | 复用，`sceneId` 指向自建场景即可 |
| 题库版本化 | 自建场景不进 `content/scene-bank.yaml` |
| 管理台 | 新增「自定义场景审核」标签页，显示待审核数量 |

## 10. 质量与安全

1. **真实性**：AI 起草不得编造公司内部信息；背景里出现具体公司名时提示「请确认公开信息准确」。
2. **敏感信息**：保存前扫描手机号、身份证、邮箱等，命中则提示删除，不阻断（用户可能故意写）。
3. **滥用**：每人每天创建上限 10 个（可配）；单用户私有场景上限 50 个；超限提示删除旧场景。
4. **隔离**：他人的私有场景不出现在列表、搜索、推荐、题库导出里；直接访问返回 404（不暴露存在性）。
5. **审核**：提交审核后进入管理员队列；通过则 `visibility='public'` 并标记来源用户（匿名展示），驳回要填理由。

## 11. 界面

### 11.1 列表页（场景训练页新增入口）

```
[我的场景]  3 个 · 2 个已发布
┌────────────────────────────────────────────┐
│ 字节跳动-后端开发-二面     中级 · 技术二面   │
│ 4 个问题 · 练过 3 次 · 私密                 │
│ [试练] [编辑] [分享] [提交审核]             │
└────────────────────────────────────────────┘
```

### 11.2 创建页（三步）

```
第一步 基本信息：标题 / 行业 / 岗位 / 阶段 / 难度 / 角色名
第二步 对话素材：背景 / 目标 / 开场白 / 必问题（可加「考察维度」）
第三步 预览确认：[从 JD 起草] [从内置复制] 两个快捷入口在顶部
```

### 11.3 预览页

按面试官视角展示：开场白 → 问题 1..N，每题右侧标注考察维度；底部「试练一场」。

## 12. 验收标准

| 编号 | 验收 | 判定 |
|---|---|---|
| S-01 | 3 分钟内创建并试练一场自建场景 | 手工计时 |
| S-02 | 自建场景报告的四维分与证据完整 | 报告页检查 |
| S-03 | 他人私有场景不可见、不可练 | 用另一个账号访问返回 404 |
| S-04 | JD 起草的问题都能在 JD 里找到依据 | 人工抽查 5 份 |
| S-05 | 提交审核 → 管理员通过 → 出现在其他学员列表 | 端到端 |
| S-06 | 自建场景默认不进入个性化计划 | 生成计划后检查任务场景来源 |
| S-07 | 超过每日上限被拒并给出可读提示 | 连续创建 11 个 |

## 13. 工作量与分期

| 阶段 | 内容 | 估时 |
|---|---|---|
| P0 | `scenes` 加字段 + 迁移；CRUD API；列表/创建/预览页；私有场景可试练 | 2–3 天 |
| P1 | 从 JD 起草（提示词 + 预览确认） | 1–2 天 |
| P2 | 分享试练链接、提交审核、管理员审核页 | 2 天 |
| P3 | 使用统计、复制率高场景推荐、模板市场 | 后续 |

## 14. 风险与开放问题

1. **题目质量**：用户可能写出「没有明确考察点」的问题。缓解：表单提示 + 预览页给「这条问题偏笼统」的启发式提醒。
2. **公共库污染**：审核标准需要一条硬线（是否包含真实公司名、是否有可考察维度）。
3. **与题库版本化的边界**：自建场景不导出，避免 `content/scene-bank.yaml` 被个人数据污染。
4. **开放问题**：是否允许教师为班级创建场景模板？建议 P3 再议。
