# 部署指南（生产）

> 目标：一台 Linux 服务器 + 一个域名，30 分钟内把言阶跑起来，并具备备份、升级、回滚与冒烟检查。
> 适用版本：后端 FastAPI + MySQL 8 + Redis 7；前端 Vue 构建后由 nginx 托管。

---

## 1. 架构

```
                HTTPS (443)
 用户浏览器 ─────────────────▶ 宿主机 nginx / Caddy（TLS 终止）
                                    │
                                    ▼
                        web 容器（nginx:80）
                        ├─ /            前端静态资源（SPA）
                        ├─ /api/*       反向代理 → backend:8081
                        ├─ /media/*     录像 / 微课 / TTS
                        └─ /api/v1/voice/ws  WebSocket 升级
                                    │
                                    ▼
                        backend 容器（uvicorn 单进程）
                        ├─ MySQL 8（容器内网，不对外）
                        ├─ Redis 7（会话与限流）
                        └─ 火山引擎 / DeepSeek（外部 API）
```

数据库与 Redis **不对公网暴露**；只有 `web` 映射 80 端口，TLS 由宿主机反代负责。

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 服务器 | 2 核 4GB 起（启用本地语音模型建议 4 核 8GB） |
| 系统 | Ubuntu 22.04 / Debian 12（其他发行版同理） |
| Docker | 24+，含 compose v2 |
| 域名 | 已解析到服务器 IP |
| 证书 | Let's Encrypt（certbot）或云厂商证书 |
| 外部服务 | DeepSeek API Key；语音功能需要火山引擎凭证 |

## 3. 首次部署

```bash
# 1) 拉代码
git clone https://github.com/Wjb-1233/yanjie-career-coach.git
cd yanjie-career-coach

# 2) 准备环境变量
cp .env.production.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # 生成 JWT_SECRET
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # 生成 MYSQL_PASSWORD / REDIS_PASSWORD
# 编辑 .env：至少填 PUBLIC_ORIGIN、JWT_SECRET、MYSQL_*、REDIS_PASSWORD、LLM_API_KEY

# 3) 构建并启动
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d

# 4) 迁移数据库（首次与每次升级都要执行）
docker compose -f docker-compose.prod.yml run --rm backend alembic upgrade head

# 5) 冒烟检查
python3 scripts/smoke_test.py --base http://127.0.0.1 --api-only
```

`docker compose ps` 应看到 `web`、`backend`、`mysql`、`redis` 四个服务均为 `healthy`。

## 4. 配置 HTTPS

宿主机安装 nginx 与 certbot（web 容器只监听 80，TLS 在宿主机做）：

```nginx
# /etc/nginx/sites-available/yanjie
server {
    listen 80;
    server_name your-domain.com;
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    client_max_body_size 220m;

    location / {
        proxy_pass http://127.0.0.1:80;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600s;      # WebSocket 长连接
        proxy_buffering off;           # SSE 流式回复
    }
}
```

```bash
# /etc/nginx/nginx.conf 的 http 块内补充：
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

sudo certbot --nginx -d your-domain.com
sudo nginx -t && sudo systemctl reload nginx
```

> 若用 Caddy：`your-domain.com { reverse_proxy 127.0.0.1:80 }` 即可自动签发证书。

## 5. 升级

```bash
git pull
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml run --rm backend alembic upgrade head
docker compose -f docker-compose.prod.yml up -d
python3 scripts/smoke_test.py --base https://your-domain.com
```

数据库迁移只前进不回退；回滚见 §7。

## 6. 备份与恢复

```bash
# 备份（数据库 + 媒体），默认保留 14 天
./scripts/backup.sh /backup/yanjie

# 恢复数据库
gunzip -c /backup/yanjie/db-YYYYmmdd-HHMMSS.sql.gz \
  | docker compose -f docker-compose.prod.yml exec -T mysql \
      sh -c 'exec mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"'

# 恢复媒体文件
docker run --rm -v career-coach-prod_recordings:/data \
  -v /backup/yanjie:/backup alpine:3.20 \
  sh -c 'cd /data && tar xzf /backup/media-YYYYmmdd-HHMMSS.tar.gz'
```

建议把备份目录挂到对象存储或另一台机器，并用 cron 每天执行：

两种定时方式，二选一：

```cron
# crontab -e
30 3 * * * cd /srv/yanjie && ./scripts/backup.sh /backup/yanjie >> /var/log/yanjie-backup.log 2>&1
```

```bash
# systemd timer（日志进 journal，失败可从 systemctl status 看到）
sudo cp deploy/yanjie-backup.service deploy/yanjie-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now yanjie-backup.timer
systemctl list-timers yanjie-backup.timer
```

两种方式都会保留最近 14 天，并支持 `Persistent=true`（关机错过也会补跑一次）。

## 8. 监控指标

后端在 `/metrics` 暴露 Prometheus 文本指标（**不经过 web 反向代理**，公网不可达；监控机需与容器网络互通或走内网地址）。

| 指标 | 说明 |
|---|---|
| `http_requests_total{method,route,status}` | 请求数，`route` 是路由模板，不含用户 ID |
| `http_request_duration_seconds_bucket/sum/count` | 延迟直方图，可算 P95 |
| `http_errors_total{route}` | 5xx 次数 |
| `app_events_total{event,outcome}` | 业务事件：`evaluation`（ok/degraded）、`analysis_task`（failed）、`scene_draft`（degraded） |
| `process_uptime_seconds` / `process_resident_memory_bytes` | 进程存活与内存 |
| `app_events_total{event="client_error"}` | 前端上报的未捕获异常 / 白屏（`POST /api/v1/client-errors`） |

示例配置：

```bash
# 监控机上
scp deploy/prometheus.example.yml   monitor:/etc/prometheus/prometheus.yml
scp deploy/prometheus-rules.example.yml monitor:/etc/prometheus/yanjie-rules.yml
```

自带四条告警：5xx 比例 >5%、P95 >3s、10 分钟无请求、降级评分占比 >20%、分析任务连续失败 >3 次。

快速自查：

```bash
curl -s http://127.0.0.1:8081/metrics | grep -E 'http_requests_total|app_events_total' | head
```

## 9. 日志与排查

```bash
docker compose -f docker-compose.prod.yml logs -f backend     # 应用日志（含 request_id）
docker compose -f docker-compose.prod.yml logs -f web         # 访问日志
docker compose -f docker-compose.prod.yml exec backend python -c "import app.main"  # 检查依赖
curl -s https://your-domain.com/healthz                        # 负载均衡探活
curl -s https://your-domain.com/api/v1/ready                   # 数据库/LLM 状态
```

常见问题：

| 现象 | 排查 |
|---|---|
| 启动即退出，日志提示生产配置不安全 | `.env` 里 `JWT_SECRET`/`LLM_API_KEY`/`REDIS_PASSWORD` 未替换，或 `CORS_ORIGINS` 不是 https |
| `ready` 返回 503 | 看 `checks`：数据库连不上、Redis 未启用、LLM Key 无效 |
| 语音连不上 | 宿主机 nginx 未转发 `Upgrade` 头；或未开 `proxy_read_timeout` |
| 上传录像 413 | 宿主机 nginx `client_max_body_size` 小于 220m |
| 内存占用高 | 本地语音模型常驻；可把 `MODEL_WARMUP_ENABLED=false` 或扩容到 8GB |

## 10. 端到端检查（可选，发布前）

接口冒烟之外，浏览器端到端覆盖“注册 → 看板 → 场景库 → 我的场景”这条真实用户路径：

```bash
cd frontend
npm ci
npx playwright install chromium      # 首次
npx playwright test                  # 需要后端 8081、前端 5173 已启动
```

- 本地没有 Playwright 浏览器时，可用系统 Chrome：`PW_CHANNEL=chrome npx playwright test`
- 指定其他地址：`E2E_BASE=https://your-domain.com npx playwright test`
- 失败会在 `frontend/test-results` 留下截图、trace 与页面快照；CI 会自动上传

## 11. 审计与数据合规

**管理台留痕**：所有 `POST/PUT/PATCH/DELETE /api/v1/admin/*` 成功后写入 `audit_logs`（操作人、方法、路由、目标 ID、IP、request_id、时间），写失败只记日志不影响业务。

```bash
# 管理员查看最近操作
curl -s -H "Authorization: Bearer <admin-token>" \
  'https://your-domain.com/api/v1/admin/audit-logs?size=20'
```

**个人数据导出**：学员在「个人资料 → 我的数据」一键导出 JSON，或调用 `GET /api/v1/auth/me/export`。包含账号资料、逐轮原文、评分与证据、训练计划、话术、故事；不包含他人数据与内部字段。

**注销账号（数据删除）**：学员在「个人资料 → 注销账号」输入当前密码与「注销」确认后，系统删除账号、训练记录、评分、话术、计划，以及录像与分段文件；操作不可恢复，演示账号受保护。对应接口 `DELETE /api/v1/auth/me/delete`。

## 12. 安全清单（上线前逐项确认）

- [ ] `.env` 未提交到仓库，权限 `600`
- [ ] `JWT_SECRET`、数据库、Redis 密码均为随机强口令
- [ ] 生产环境 `AUTO_CREATE_SCHEMA=false`，迁移走 Alembic
- [ ] `CORS_ORIGINS` 只有自己的 https 域名
- [ ] 数据库与 Redis 端口未对公网开放（compose 中只 `expose`）
- [ ] 演示账号开关在生产关闭（`DEMO_LOGIN_ENABLED=false`，如有）
- [ ] 宿主机防火墙只开 22 / 80 / 443
- [ ] 备份任务已配置并演练过一次恢复
- [ ] `scripts/smoke_test.py` 全绿

## 13. 容量与伸缩（可选）

- 应用无状态（会话与限流在 Redis），可水平扩容 `backend`；后台分析任务领取已用 `SKIP LOCKED`，多实例不会重复跑。
- 但每个实例都会常驻语音模型，按内存决定副本数；纯文字场景可 `MODEL_WARMUP_ENABLED=false`。
- 录像增长快，建议 `RECORDING_RETENTION_DAYS=30` 并结合对象存储做长期归档。
